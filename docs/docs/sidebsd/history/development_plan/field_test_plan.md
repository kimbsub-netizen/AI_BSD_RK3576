# ADAS 시스템 필드 테스트(Field Test) 수행 계획서

**작성일**: 2026-07-17
**대상 시스템**: Rockchip (2~3 TOPS) 기반 단일 카메라 후방 ADAS (충돌 경고 및 속도 추적 시스템)

---

## 1. 개요 및 테스트 원칙

실제 차량에 탑재하여 진행하는 필드 테스트는 **"단계적 랩(Lab) 검증"**과 **"실시간 엣지(Edge) 검증"** 두 단계로 나누어 진행하는 것이 업계 표준이자 가장 안전한 방법입니다. 처음부터 락칩(Rockchip) 단말기에서 실시간으로 로깅하고 튜닝하는 것은 도로 위에서 위험할 뿐 아니라 디버깅이 불가능에 가깝습니다.

따라서 다음과 같이 **3 Phase(단계)**로 나누어 필드 테스트를 수행합니다.

---

## Phase 0: 정지 상태 환경 통제 설정 (Stationary Setup)

1. **카메라 마운팅 고정**
   * 차량 후방(또는 전방) 유리에 카메라를 설치하고 테이프나 마커 등으로 **카메라 각도가 절대 틀어지지 않게 고정점(마킹)**을 표시합니다.
2. **거리 캘리브레이션 측정**
   * 넓은 공터에서 차량 뒤쪽으로 2m, 5m, 10m, 18m, 30m 지점에 라바콘(또는 잘 보이는 물체)을 세워둡니다.
   * 카메라 영상을 녹화하거나 캡처 프로그램(`frame_capture_tool.py`)을 이용해 바닥면에 닿는 `y_pixel` 값을 얻어냅니다.
   * `config.py`의 `CALIBRATION_DATA`를 업데이트하여 1차 기준값을 설정합니다.

---

## Phase 1: 원본 주행 영상 수집 (Raw Data Collection)
> **목적**: PC/랩(Lab) 환경에서 알고리즘과 파라미터를 안전하게 깎고 다듬기 위한 "순수 데이터" 확보

1. **설정**: 락칩이나 라즈베리파이 등의 단말기에서는 **무거운 ADAS 추론(YOLO)을 돌리지 않습니다.** 오직 고품질의 **원본 동영상(Raw MP4/MKV)만 저장**하도록 설정합니다.
2. **주행 테스트**: 
   * **도심 주행**: 꽉 막힌 정체 구간, 신호 대기선 접근, 끼어들기가 빈번한 시내 주행 (약 30분)
   * **고속도로 주행**: 80~100km/h로 주행 시 뒤에서 빠르게 달려오는 차량, 고속 추월 차량 발생 구간 (약 30분)
   * **악천후/야간 (선택)**: 터널 진입/진출, 야간 가로등 골목, 우천 시 주행
3. **특이사항 수기 기록 (Ground Truth)**
   * 보조석의 동승자가 초시계를 들고 특이 상황을 기록합니다.
   * *예) 14분 20초: 흰색 SUV가 너무 확 끼어들어서 브레이크 밟음 (이때 경보가 울려야 함)*

---

## Phase 2: 랩 검증 및 파라미터 튜닝 (Lab Simulation)
> **목적**: 수집해 온 원본 영상을 랩(PC)의 `normalized_adas_system.py`에 밀어 넣고 최적의 튜닝값을 찾아냅니다.

1. **데이터 셋업**: Phase 1에서 가져온 영상들을 PC의 `video/in/` 폴더에 넣고 스크립트를 돌립니다.
2. **시각화 디버깅**: 바운딩 박스, TTC 수치, 속도가 영상 위에 찍히는 `output_video.mp4` 결과물을 눈으로 확인합니다.
3. **파라미터 집중 튜닝 (`config.py`)**:
   * 동승자가 적어둔 "14분 20초 (끼어들기 위험 상황)"에 실제 빨간색 알람이 뜨는지 확인합니다.
   * 안 떴다면? → `TTC_DANGER_THRESHOLD`를 늘리거나 `VELOCITY_SMOOTH_WINDOW` 반응성을 높입니다.
   * 차가 너무 멀리 있는데 픽셀이 튀어서 가짜 알람(오탐)이 뜬다면? → `MAX_VALID_DISTANCE`를 좁히거나 `MIN_APPROACH_SPEED`를 올려 도심 꼬리물기를 차단합니다.
   * 곡선 도로에서 알람이 안 맞다면? → `lane_tuner.py`를 열어 영상에 맞춰 차선 인식률을 높입니다.
4. **결과 확정**: "이 튜닝값 설정이면 실제 운전할 때 짜증 안 나고 딱 좋을 타이밍에 울려준다"는 "황금 파라미터(Golden Param)"를 확정합니다. 

---

## Phase 3: 엣지(Edge) 실환경 라이브 검증 (Real-time Test)
> **목적**: 완성된 로직을 락칩에 올렸을 때 프레임 저하(FPS Drop) 없이 동일하게 동작하는지 최종 확인

1. **단말기 세팅**: Phase 2에서 찾아낸 파라미터(`config.py`)를 락칩 NPU 보드에 이식합니다. (`FRAME_SKIP`을 2 정도로 올려 15fps 수준의 추론 속도 확보)
2. **CSV 로그 출력 설정**: 실시간 환경에서는 리소스 절약을 위해 영상 위에 박스를 그리고 동영상을 녹화(인코딩)하는 로직을 최소화하거나 끕니다. 대신 경고 발생 시 **날짜, 시간, 거리, 속도, TTC, 경고수준을 텍스트 로그(Text/CSV)로 실시간 저장**하도록 코드를 수정/설정합니다.
   ```csv
   [2026-07-18 14:02:11.312], DANGER, Dist: 4.2m, Vel: 5.6m/s, TTC: 0.75s
   [2026-07-18 14:15:00.123], WARNING, Dist: 15m, Vel: 4.1m/s, TTC: 3.6s
   ```
3. **최종 주행**: 시스템을 켜고 실주행을 나갑니다. 부저(스피커)를 달아서 실시간으로 소리가 울리는지 귀로 체감(Real Feel) 합니다.
4. **검토**: 주행을 마치고 락칩의 CSV 로그를 뽑아내어, "소리가 제대로 된 상황에서 울렸는지" 사후 분석합니다. 이때 문제가 없으면 상용화 배포(v1.0)를 확정합니다.

---

### 💡 팁과 주의사항
* 락칩 보드에서 1080p 영상을 그대로 받아 YOLO와 박스 그리기(Drawing) 처리를 동시에 돌리면 NPU 오프로딩을 하더라도 CPU 단에서 엄청난 발열과 딜레이가 발생합니다.
* 랩 테스트에서 로직 검증이 끝났다면, 엣지(Phase 3)에서는 `cv2.putText`나 영상 저장을 과감하게 빼버리고 텍스트 로깅+시리얼 통신(부저/비프음)으로만 처리하는 것이 임베디드 반응 속도를 극대화하는 비결입니다.
